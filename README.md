# Capsula: ИИ-стилист

Веб-приложение без сборки: статика в `public/` и API `/api/*`, которое само собирает промпты, вызывает модель и решает, какая часть результата бесплатна.

**Пошаговая инструкция** (запуск, деплой на Cloudflare, секреты, логи, частые ошибки, смена моделей): [docs/guide.md](docs/guide.md). Тестовый адрес: https://capsula-claude.yaroslav-galevich.workers.dev

Что умеет:

1. **Профиль**: анализ фото (цветотип из 12 сезонов и соседний сезон, пропорции, фигура, рост из анкеты) и подбор стилей и силуэтов с описанием.
2. **Гардероб**: главный способ это до 10 своих фото в образах (селфи в зеркале, снимки с прогулок). Модель находит на всех фото уникальные вещи, браузер вырезает каждую, повторы склеиваются, уже имеющиеся вещи второй раз не добавляются, импорт можно отменить. Запасной способ: фото вещей по одной, распознавание пачками по 6, три пачки параллельно. Всё правится вручную.
3. **Образы**: готовые луки только из вашего гардероба с учётом пожеланий по стилю.
4. **Капсула**: палитра, что оставить, что докупить (с приоритетом, ценой и парами), образы капсулы. Работает и с гардеробом, и с нуля.
5. **Поиск**: ссылки на Lamoda, Wildberries, Ozon, Яндекс Маркет, Google Покупки, ASOS, Zara, Pinterest и поиск конкретных моделей через ИИ с веб-поиском (OpenRouter).

## Как устроено

Браузер отправляет на сервер только данные: фото, анкету, гардероб, пожелания. Промпты и задачи (`server/modules/<id>.mjs`), выбор модели, проверка входа и граница бесплатного плана живут на сервере (`server/api.mjs`). Ключи провайдеров в браузер не попадают, а сервер не пересылает провайдеру произвольные запросы: раньше `/api/llm` с серверным ключом мог использовать как бесплатный API любой, кто нашёл адрес.

| Маршрут              | Что делает                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/config`    | готов ли сервер, включён ли платный доступ, цена, ссылка на оплату, доступен ли веб-поиск                                            |
| `POST /api/task`     | задача `analysis`, `wardrobe`, `outfits`, `looks`, `capsule` или `search`; ответ потоком SSE: `progress`, затем `result` или `error` |
| `POST /api/activate` | код Pro → подписанный токен; код разработчика → режим разработчика                                                                   |
| `POST /api/unlock`   | с Pro-токеном вскрывает конверты с полными результатами                                                                              |

Данные пользователя (фото, гардероб, результаты) хранятся только в IndexedDB браузера. Сервер ничего не сохраняет: фото уходят провайдеру модели на время запроса.

**Важно про модель по умолчанию.** Сейчас во всех слотах стоит `muse-spark-1.3-contributor`. «Contributor» значит, что Meta обучается на запросах: у этой модели на OpenRouter нет провайдера с `data_collection = deny`, поэтому для неё сервер сам ставит `allow`. То есть фото пользователей уходят в обучение модели. Для обычных моделей политика остаётся `deny` (только провайдеры без хранения и обучения). Явно задаётся переменной `OPENROUTER_DATA_COLLECTION`. Перед запуском на живых пользователях это надо либо поменять, либо прямо написать в согласии на обработку фото.

## Платный доступ

Включается переменной `PRO_SECRET`. Без неё всё открыто (режим пилота).

- **Бесплатно**: цветотип, соседний сезон, 4 лучших цвета, тип фигуры, один стиль; гардероб из фото образов и распознавание вещей; первые 2 образа; концепция, палитра и 3 самые важные покупки капсулы; ссылки на магазины.
- **Pro**: остальная палитра, нейтрали, цвета, которых избегать, металлы, пропорции, силуэты по зонам, ткани, итог, все образы, капсула целиком, поиск с ИИ.
- Если фигуру по фото определить не удалось, этот блок не закрывается: продавать «не определено» нельзя.

Полный результат генерируется сразу, бесплатному пользователю приходит урезанная версия и **конверт**: полный результат, зашифрованный AES-GCM ключом из `PRO_SECRET`. После покупки сервер вскрывает конверт, и человек видит ровно то, что ему показали частично, без повторной генерации и без базы данных.

**Pro-токен** подписан HMAC и содержит срок действия. Сейчас его выдают в обмен на код из `PRO_CODES`. Это ручной режим для проверки спроса: продавать коды через ссылку `PAY_URL` (Boosty, Tribute, YooMoney и т. п.). Для настоящей оплаты нужен вебхук платёжки, который выдаёт токен, и хранилище, чтобы код нельзя было передать другу. Коды из `PRO_CODES` многоразовые.

Лимит частоты (20 задач за 10 минут с одного IP на бесплатном плане, 120 на Pro, 10 попыток ввода кода) хранится в памяти экземпляра функции. На serverless это защита от скриптов, а не квота.

## Переменные окружения

| Переменная                                      | Зачем                                                                                                                                       |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `OPENROUTER_API_KEY`                            | ключ OpenRouter (основной провайдер)                                                                                                        |
| `OPENCODE_GO_API_KEY`                           | ключ OpenCode Go, только для тестов (см. ниже)                                                                                              |
| `LLM_PROVIDER`                                  | `openrouter` или `opencode-go`; по умолчанию тот, чей ключ задан                                                                            |
| `MODEL_VISION`, `MODEL_TEXT`                    | модели для фото и для текста; по умолчанию `meta/muse-spark-1.3-contributor` (OpenCode Go: `muse-spark-1.3-contributor`)                    |
| `MODEL_DETECT`                                  | модель для вещей на фото образов (рамки и повторы); по умолчанию тоже Muse Spark. Рамки у неё хуже, см. «Модели»                            |
| `MODEL_FALLBACK`                                | запасная модель OpenRouter для фото и текста, по умолчанию `openai/gpt-6-luna`; пустая строка отключает                                     |
| `MODEL_DETECT_FALLBACK`                         | запасная модель для `detect`, по умолчанию `qwen/qwen3.8-flash`. Общий `MODEL_FALLBACK` её не меняет: не каждая модель умеет ставить рамки  |
| `EFFORT_VISION`, `EFFORT_TEXT`, `EFFORT_DETECT` | effort рассуждений; по умолчанию `low` для фото, `minimal` для текста и `detect` (Muse Spark не принимает `none`)                           |
| `OPENROUTER_DATA_COLLECTION`                    | `deny` или `allow`; по умолчанию `deny`, а для моделей `-contributor` `allow` (иначе у них нет ни одного провайдера)                        |
| `LOG_LEVEL`                                     | `info` (по умолчанию): строка на задачу; `debug`: каждый запрос к модели; `trace`: ещё промпты и ответы. См. «Логи и отладка»               |
| `LOG_FORMAT`                                    | `json` (по умолчанию, для Cloudflare и Netlify) или `pretty` (для терминала)                                                                |
| `OPENROUTER_SORT`                               | как OpenRouter выбирает провайдера модели: `throughput` (по умолчанию), `latency` или `price`                                               |
| `MAX_TOKENS`                                    | потолок ответа вместе с рассуждениями, по умолчанию 24000; 0 значит не передавать                                                           |
| `PRO_SECRET`                                    | включает платный доступ; ключ подписи токенов и шифрования конвертов. Не меняйте без нужды: старые токены и конверты перестанут открываться |
| `PRO_CODES`                                     | коды Pro через запятую, `КОД` или `КОД:дней` (по умолчанию 30 дней)                                                                         |
| `PRO_PRICE`                                     | цена для окна оплаты, например `490 ₽ в месяц`                                                                                              |
| `PAY_URL`                                       | https-ссылка на оплату                                                                                                                      |
| `ADMIN_CODE`                                    | код разработчика: всё открыто, в настройках можно подменить провайдера, модель и effort, в ошибках виден сырой ответ модели                 |

## Модели

### Muse Spark 1.3 Contributor (модель по умолчанию с 23 октября 2026)

Замер 23 октября 2026 на 4 стоковых фото (портрет для анализа, 3 фото образов), весь путь через API как из браузера. Время до конца ответа, в скобках время до первого токена.

| Задача               | OpenRouter    | OpenCode Go (Responses API) | Cloudflare Workers + OpenRouter |
| -------------------- | ------------- | --------------------------- | ------------------------------- |
| Анализ фото          | 24 с (3.5 с)  | 36 с (19 с)                 | 22 с                            |
| Гардероб из 3 фото   | 13 с (3.6 с)  | 11 с (7.6 с)                | 16 с                            |
| Образы               | 9 с (2.4 с)   | 15 с (8.8 с)                | 10 с                            |
| Капсула              | 21 с (2.9 с)  | 29 с (10.8 с)               | 19 с                            |
| Поиск с ИИ (Exa)     | 9 с, $0.0074  | нет веб-поиска              | только Pro                      |
| Весь путь без поиска | около $0.0027 | из лимита подписки          | около $0.0023                   |

- Цветотип стабилен между провайдерами: оба раза «Мягкая осень», соседний «Мягкое лето».
- **Рамки вещей (`detect`) у Muse Spark плохие на сложных фото**: на простом фото в полный рост точные, но на фото с сумками и в куртке перчатки обводятся по всему телу, очки и юбка мимо. Gemini 3.8 Flash на тех же фото точен (12 с, $0.010), Qwen 3.8 Flash через OpenCode Go хуже Gemini и шёл 188 с. Вернуть точные рамки: `MODEL_DETECT=google/gemini-3.8-flash`.
- **Веб-поиск**: без явного движка OpenRouter включал для Muse Spark её родной поиск, тот не отдаёт источники и выдумывал ссылки вида `wildberries.ru/catalog/.../12345678/`. Теперь движок `exa` задан явно: ссылки из реальной выдачи (ЦУМ, Lime, USmall), все проверены по источникам, в 3 раза дешевле.
- OpenCode Go отвечает медленнее на старте: 6-12 с до первого байта против 0.6-1.6 с у OpenRouter.

Вещи на фото образов (слот `detect`, октябрь 2026, 6 фото одного человека, 10 уникальных вещей, 18 повторов):

| Модель                         | Рамки                                    | Один запрос на все фото                | Заметки                                             |
| ------------------------------ | ---------------------------------------- | -------------------------------------- | --------------------------------------------------- |
| `google/gemini-3.8-flash`      | точные                                   | 10 из 10, повторы верно, 13 с, $0.011  | по умолчанию; рассуждения не выключаются, `minimal` |
| `qwen/qwen3.8-flash`           | точные                                   | 10 из 10, повторы верно, 30 с, $0.0025 | запасная: в 4 раза дешевле, в 2 раза медленнее      |
| `deepseek/deepseek-v4.1-flash` | мимо вещи на сложных фото (тренч, брюки) |                                        | для рамок не годится                                |

Раздельный поиск по каждому фото и склейка повторов по тексту ошибается: «чёрные джинсы» и «чёрные брюки» с разных фото становятся двумя вещами. Поэтому модель видит все фото сразу, а с уже имеющимися вещами сверяется по таблице миниатюр: 36 миниатюр одной картинкой стоят как одно фото (около 1100 токенов), а не как 36.

Цветотип по фото у пограничных внешностей плавает даже при `temperature: 0`: один и тот же снимок давал то «Тёмную осень», то «Тёмную зиму». Поэтому модель выбирает сезон строго из 12 названий и называет соседний сезон. При повторе человек видит ту же пару.

**OpenCode Go** рассчитан на трафик кодинг-агентов: без заголовка `x-opencode-session` запросы отклоняются, трафик мониторится на злоупотребления. Это подписка с месячным лимитом, а не бесплатный доступ. Бесплатные `-free` модели работают только из самого OpenCode.

Muse Spark и GPT в OpenCode Go отвечают только по OpenAI Responses API (`/responses`), на `chat/completions` они отвечают `ModelProtocolUnsupported`. Раньше из-за этого они не работали. Теперь клиент (`server/llm.mjs`) шлёт им запросы в Responses API, а для незнакомой модели сам переключает протокол по этой ошибке и запоминает выбор на 30 минут. Gemini 4 Argon и Claude там требуют свои протоколы (generateContent и Messages), их клиент пока не умеет. Для продакшена используйте OpenRouter: он быстрее на старте и умеет веб-поиск.

## Запуск локально

```bash
OPENROUTER_API_KEY=sk-or-... npm run dev   # http://localhost:8888
PRO_SECRET=dev PRO_CODES=TEST ADMIN_CODE=me OPENROUTER_API_KEY=sk-or-... npm run dev   # с платным доступом
npm test
```

Ключи удобнее положить в `.dev.vars` в корне (формат `KEY=VALUE`, как у `wrangler dev`, файл в `.gitignore`): dev-сервер берёт оттуда всё, чего нет в окружении.

Нужен Node 20+. Зависимостей нет. Dev-сервер слушает только `127.0.0.1` и принимает `/api/*` только с Host `localhost`/`127.0.0.1`, потому что использует ключи из окружения.

## Логи и отладка

Где смотреть:

| Где                         | Что видно                                                                                                                    | Как открыть                                                                  |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Вкладка «Логи» в приложении | последние 40 задач браузера: вход, промпт, каждый запрос к модели, статусы, повторы, токены, цена, сырой ответ; копия и JSON | Настройки → Ввести код → `ADMIN_CODE` (в `npm run dev` по умолчанию `dev`)   |
| Терминал `npm run dev`      | каждый запрос к модели одной строкой; с `LOG_LEVEL=trace` ещё промпты и ответы                                               | по умолчанию `LOG_LEVEL=debug`, `LOG_FORMAT=pretty`                          |
| `.logs/api.jsonl`           | все события со всеми подробностями, включая промпты и ответы модели, при любом `LOG_LEVEL`                                   | `npm run logs`, `npm run logs -- <код>`, `-- --errors`, `-- --full`, `-- -f` |
| Cloudflare Workers          | строка JSON на событие, ищется по `rid`                                                                                      | `npm run logs:worker` (это `wrangler tail`) или Workers → воркер → Logs      |
| OpenRouter                  | сама генерация по её id (`id=gen-...` в логе)                                                                                | openrouter.ai → Activity                                                     |

У каждой задачи есть код запроса (`rid`, 10 символов). Он приходит в заголовке `x-request-id`, в результате и в ошибке, его видно под текстом ошибки в приложении. В режиме разработчика рядом ссылка «открыть лог» на запись журнала. По коду строка находится в любом из логов.

Что пишется о каждой задаче: провайдер, модель и запасная модель, effort, политика данных, размеры фото (сами фото никогда), протокол и параметры запроса, HTTP-статус и время до первого байта, время до первого токена и до конца, повторы и их причина, отброшенные параметры, смена протокола и effort, разбор JSON (починен ли), какая модель и какой провайдер ответили на самом деле, токены (в том числе рассуждения) и цена, текст ошибки провайдера целиком.

Уровни `LOG_LEVEL` для серверных логов: `info` по умолчанию (строка на задачу, без персональных данных), `debug` (каждый запрос к модели), `trace` (ещё промпты с анкетой и ответы модели). Запросы с кодом разработчика пишутся как `debug` при любом уровне, а всю трассу с промптом и ответом получает браузер разработчика, не консоль. На тестовом воркере `capsula-claude` стоит `LOG_LEVEL=debug`.

Первая находка этих логов: в режиме разработчика пустой effort из настроек («как на сервере») стирал серверный, и модель думала на уровне провайдера по умолчанию. Гардероб из фото шёл 56 с вместо 11, образы 51 с вместо 15. Исправлено.

## Деплой

### Cloudflare Workers

Ожидание ответа модели не считается в лимит CPU, поэтому долгие ответы не обрываются. Технически это лучшая площадка для этого кода, но с июня 2025 российские провайдеры замедляют соединения с Cloudflare. Если аудитория в России, проверьте адрес с российского интернета без VPN (подробнее в `docs/product/README.md`, раздел 9).

```bash
npx wrangler deploy --name capsula-claude     # тестовый воркер: https://capsula-claude.yaroslav-galevich.workers.dev
npx wrangler secret put OPENROUTER_API_KEY --name capsula-claude   # и остальные переменные
```

Без `--name` воркер называется `capsula` (из `wrangler.jsonc`).

Настройки в `wrangler.jsonc`: статика из `public/`, `/api/*` идёт в `worker/index.mjs`.

### Netlify

Netlify обрывает функцию примерно через 30 секунд, и стриминг этот срок не продлевает (замерено в октябре 2026 на бесплатном плане: обрывы на 30.6 и 31.1 с). Обычно задачи укладываются в 10-20 секунд, но редкий медленный ответ провайдера обрывается. Клиент в этом случае один раз повторяет задачу сам.

1. Репозиторий в Netlify: _Add new site → Import from Git_. Настройки подтянутся из `netlify.toml` (publish `public`, функции `netlify/functions`).
2. _Site configuration → Environment variables_: переменные из таблицы выше.
3. Либо через CLI: `npx netlify deploy --prod`.

### Cloudflare Pages

Тот же код, обёртка в `functions/api/[[path]].js`. _Workers & Pages → Create → Pages → Connect to Git_, build command пустой, output directory `public`, переменные в _Settings → Variables and secrets_.

Заголовки безопасности (CSP, запрет фреймов и т. п.) лежат в `public/_headers`, его читают и Netlify, и Cloudflare.

## Ограничения

- Качество анализа зависит от света и модели. Рост по фото не определяется надёжно, укажите его в анкете.
- Вещи из фото образов вырезаются вместе с тем, что вокруг: сумка на фоне свитера, ботинки с краем брюк. Для каталога этого хватает, для карточки «как в магазине» нужна генерация изображения (см. продуктовый разбор). Модель считает, что на всех фото один человек: фото с другими людьми дают лишние вещи.
- Ссылки от ИИ-поиска проверяются по списку источников веб-поиска, если провайдер его отдаёт. Если нет, они помечаются как непроверенные.
- Нет аккаунтов и синхронизации между устройствами: Pro-токен живёт в браузере, где его активировали.
