# Capsula: ИИ-стилист (MVP-пилот)

Веб-приложение без сборки: статика в `public/` и один прокси `/api/llm` к LLM-провайдерам.

Что умеет:

1. **Профиль**: анализ фото (цветотип, пропорции, фигура, рост из анкеты) и подбор стилей и силуэтов с описанием.
2. **Гардероб**: загрузка вещей фото, распознавание (категория, цвет, ткань, сезон), ручная правка.
3. **Образы**: готовые луки только из вашего гардероба с учётом пожеланий по стилю.
4. **Капсула**: палитра, что оставить, что докупить (с приоритетом, ценой и парами), образы капсулы. Работает и с гардеробом, и с нуля.
5. **Поиск**: ссылки на Lamoda, Wildberries, Ozon, Яндекс Маркет, Google Покупки, ASOS, Zara, Pinterest и поиск конкретных моделей через ИИ с веб-поиском (OpenRouter).

## Модели

В «Настройках» два слота, у каждого свои провайдер, модель и effort:

| Слот | Задачи | По умолчанию |
|---|---|---|
| Модель для фото | анализ клиента, распознавание вещей | OpenRouter, `meta/muse-spark-1.3-contributor`, `xhigh` |
| Модель стилиста | образы, капсула, поиск | OpenRouter, `openai/gpt-6-luna`, `xhigh` |

Провайдеры: OpenRouter, OpenCode Go (`https://opencode.ai/zen/go/v1`) и любой свой OpenAI-совместимый (Base URL + ключ). Имя модели вводится вручную, подсказки только ориентир.
Effort передаётся как `reasoning.effort` (OpenRouter) или `reasoning_effort` (остальные). Если провайдер отвечает 400 на этот параметр, запрос один раз повторяется без него.

**Приватность.** Модели `-contributor` дешевле, потому что провайдер может обучаться на запросах. В слот для фото уходят фото клиентов. Для реальных клиентов поставьте обычную `meta/muse-spark-1.3`.

## Ключи

- **Токен пилота**: переменные окружения `OPENROUTER_API_KEY` и/или `OPENCODE_GO_API_KEY`. Пользователь ничего не вводит, ключ с сервера не отдаётся в браузер.
- **Код доступа**: если задать `PILOT_ACCESS_CODE`, токен пилота выдаётся только тем, кто ввёл код в настройках. Без этого любой, кто найдёт URL, будет тратить ваши токены.
- **Свои ключи пользователей**: вводятся в настройках, лежат в `localStorage` браузера и передаются через прокси в заголовке. Прокси их не сохраняет и не логирует. Для своего провайдера серверный токен никогда не подставляется.

Данные клиентов (фото, гардероб, результаты) хранятся только в IndexedDB браузера. Сервера с базой нет. Есть выгрузка и загрузка копии в настройках.

## Запуск локально

```bash
OPENROUTER_API_KEY=sk-or-... npm run dev   # http://localhost:8888
npm test
```

Нужен Node 20+. Зависимостей нет.

## Деплой на Netlify

1. Залейте репозиторий на GitHub, в Netlify: *Add new site → Import from Git*. Настройки подтянутся из `netlify.toml` (publish `public`, функции `netlify/functions`).
2. *Site configuration → Environment variables*: `OPENROUTER_API_KEY`, при желании `OPENCODE_GO_API_KEY` и `PILOT_ACCESS_CODE`.
3. Либо через CLI: `npx netlify deploy --prod`.

Drag-and-drop папки без Git не подойдёт, функции так не деплоятся.

**Таймауты.** Ответы в режиме `xhigh` могут идти долго. Прокси стримит ответ, и поток идёт сразу, но у синхронных функций Netlify есть лимит по времени, зависящий от тарифа. Если запросы обрываются, поставьте effort `high` в настройках или используйте Cloudflare.

## Деплой на Cloudflare Pages

Тот же код, обёртка в `functions/api/llm.js`.

1. *Workers & Pages → Create → Pages → Connect to Git*, build command пустой, output directory `public`.
2. *Settings → Variables and secrets*: те же переменные.

## Структура

```
public/             статика и клиентские модули (без сборки)
  js/prompts.js     промпты стилиста и JSON-схемы ответов
  js/llm.js         клиент: стриминг, effort, разбор JSON, повтор при битом JSON
  js/views/         экраны: profile, wardrobe, looks, capsule, search, settings
lib/proxy-core.mjs  прокси (общий для Netlify и Cloudflare)
netlify/functions/  обёртка для Netlify
functions/api/      обёртка для Cloudflare Pages
test/               тесты прокси и разбора JSON
```

## Ограничения MVP

- Качество анализа по фото зависит от света и модели. Рост по фото не определяется надёжно, укажите его в анкете.
- Ссылки от ИИ-поиска проверяются по списку источников веб-поиска, если провайдер его отдаёт. Если нет, они помечаются как непроверенные.
- Нет аккаунтов и синхронизации между устройствами.
